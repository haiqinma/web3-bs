# 钱包交互错误提示

`web3-bs` 不创建 Toast、Modal 或其他 UI。它提供确定性的错误分类和中英文提示文案，DApp 使用自己的通知组件展示，并负责传入当前界面语言。

```ts
import {
  getLocalizedWalletErrorMessage,
  loginWithWalletIdentity
} from '@yeying-community/web3-bs'

try {
  await loginWithWalletIdentity()
} catch (error) {
  // locale 必须来自 DApp 当前已选语言，而不是浏览器语言。
  const message = getLocalizedWalletErrorMessage(error, { locale: currentLocale })
  toast.error(message)
}
```

`locale` 支持 `zh-CN` 和 `en-US`；`zh`、`zh-*` 归一化为 `zh-CN`，其他语言归一化为 `en-US`。如果省略，SDK 使用浏览器语言。应用可以通过 `messages` 覆盖具体错误文案：

```ts
getLocalizedWalletErrorMessage(error, {
  locale: currentLocale,
  messages: {
    userRejected: t('auth.walletCanceled'),
    walletLocked: t('auth.unlockWalletFirst')
  }
})
```

## 错误文案

格式化器返回面向用户的说明和下一步建议，不回传底层 RPC message、HTTP body 或服务端原文。日志和诊断仍应保留原始错误对象及 code；不要把本地化文案用于协议判断。

| 错误类别 | 识别条件 | 用户提示与建议 |
| --- | --- | --- |
| `userRejected` | EIP-1193 `4001`、`USER_REJECTED` | 用户取消了操作；提供重新发起入口，不自动重复弹窗 |
| `walletNotFound` | 钱包 Provider 缺失 | 提示安装或启用钱包 |
| `walletLocked` | `WALLET_LOCKED` | 提示打开钱包解锁，再由用户重试 |
| `pendingApproval` | `WALLET_POPUP_OPEN` | 提示切换到已有钱包确认窗口，不重复发送请求 |
| `unsupportedMethod` | `-32601`、`4200` 或方法不可用 | 明确当前钱包不支持；由应用提供独立的其他协议入口，不自动降级 |
| `permissionDenied` | `4100` 或 `UNAUTHORIZED` | 提示检查钱包对站点的权限 |
| `disconnected` | `4900` 或 Provider 断开 | 提示重新连接 |
| `chainDisconnected` | `4901` | 提示切换到所需网络 |
| `timeout` | 错误消息指明超时 | 提示检查钱包窗口中的待处理操作 |
| `identityNotVerified` | `IDENTITY_WALLET_NOT_VERIFIED` | 提示在钱包中完成绑定钱包账户验证 |
| `identityCredentialMissing` | `IDENTITY_CREDENTIAL_REQUIRED:*` / `IDENTITY_CREDENTIAL_MISSING:*` | 提示补全并验证应用要求的身份资料 |
| `identityScopeMismatch` | `IDENTITY_SCOPE_MISMATCH` | 提示应用登录权限配置不一致，并联系应用支持 |
| `unknown` | 未匹配上述类别 | 提示重试或联系应用支持，不暴露技术细节 |

## 语言边界

- DApp 页面中的 Toast、表单错误、登录状态由 DApp 的当前 locale 决定。DApp 应将同一 locale 传给 `getLocalizedWalletErrorMessage`。
- 钱包插件自己的连接确认、签名确认和解锁窗口属于 Wallet UI，由 Wallet 当前语言设置决定；DApp locale 不会覆盖钱包窗口语言。
- 浏览器原生 Passkey、生物识别或系统账户选择 UI 由浏览器和操作系统决定语言，DApp 与 SDK 均不能强制设置。
- 应用收到 `userRejected` 后应保持在当前登录页或表单上下文，不应将取消展示成系统故障；用户再次操作后再发起新请求。
- `unsupportedMethod` 不代表 SIWE 或其他协议失败。协议保持独立，由 DApp 明确提供另一种登录选项，不允许 SDK 静默切换协议。
